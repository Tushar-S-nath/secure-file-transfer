Fix padding-oracle asymmetry in receiver error handling

Previously: an HMAC failure sent an explicit ERROR packet with
HMAC-specific wording; a CBC padding failure sent nothing at all and
just dropped the connection. That asymmetry is exactly what a
padding-oracle attack needs.

Fix: both failure paths now go through a single _send_generic_failure()
helper that sends the exact same ERROR message regardless of which
check actually failed, plus a small fixed delay to reduce timing
distinguishability.

Added tests/test_padding_oracle_mitigation.py: an end-to-end test
proving both failure modes now produce byte-identical responses.

Verified: 107/107 relevant tests pass.
